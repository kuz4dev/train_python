# Пакетный менеджер Python: pip, виртуальные окружения и работа с пакетами

## Зачем нам вообще пакеты?

Когда мы пишем программы на Python, нам редко хочется писать всё с нуля. Нужно скачать страницу из интернета? Кто-то уже написал для этого библиотеку. Хотим работать с Excel? Тоже есть готовое решение. Распознать лицо на фотографии, построить график, обучить нейросеть — для всего этого существуют готовые **пакеты** (они же библиотеки).

Сам Python из коробки умеет многое — это так называемая **стандартная библиотека** (`os`, `json`, `math`, `random` и так далее). Но мир огромен, и всё в стандартную библиотеку не запихнёшь. Поэтому существует огромный репозиторий внешних пакетов — **PyPI** (Python Package Index), который живёт по адресу [pypi.org](https://pypi.org). Там сейчас лежит более 500 тысяч пакетов на любой вкус.

Чтобы скачать пакет с PyPI и установить его себе, нужен инструмент — **пакетный менеджер**. В Python он называется **pip**.

---

## Что такое pip

`pip` — это программа, которая идёт вместе с Python и умеет:

- скачивать пакеты с PyPI
- устанавливать их к вам в систему
- удалять
- обновлять
- показывать, что уже установлено
- сохранять список установленных пакетов в файл (чтобы потом можно было всё повторить)

Проверим, что pip у нас есть. Открываем терминал и пишем:

```bash
pip --version
```

В ответ должно прийти что-то вроде:

```
pip 24.0 from /usr/lib/python3/dist-packages/pip (python 3.12)
```

Если pip не найден, можно попробовать `pip3` или `python -m pip` — это тоже сработает.

## Основные команды pip

### Установка пакета

```bash
pip install requests
```

Этой командой мы скачиваем и устанавливаем пакет `requests` — одну из самых популярных библиотек для отправки HTTP-запросов. После установки им можно сразу пользоваться:

```python
import requests

response = requests.get("https://api.github.com")
print(response.status_code)
```

Можно установить сразу несколько пакетов:

```bash
pip install requests pandas matplotlib
```

Можно поставить конкретную версию:

```bash
pip install requests==2.31.0
```

Или сказать «не старше такой-то версии»:

```bash
pip install "requests>=2.30,<3.0"
```

### Удаление пакета

```bash
pip uninstall requests
```

pip переспросит, действительно ли вы хотите удалить. Если нужно подавить вопрос — добавьте флаг `-y`.

### Список установленных пакетов

```bash
pip list
```

Выведет таблицу с именами пакетов и их версиями.

### Информация о пакете

```bash
pip show requests
```

Покажет версию, автора, краткое описание, зависимости и где пакет физически лежит на диске.

### Обновление пакета

```bash
pip install --upgrade requests
```

## requirements.txt — список пакетов проекта

Представьте: вы написали учебную программу, которая использует `requests`, `pandas` и `matplotlib`. Вы отправляете её подруге, а она спрашивает: «А что мне нужно установить, чтобы это запустилось?»

Чтобы не объяснять каждый раз словами, делают файл `requirements.txt`. В нём построчно перечислены все нужные пакеты:

```
requests==2.31.0
pandas==2.2.0
matplotlib==3.8.2
```

Подруга у себя выполняет одну команду:

```bash
pip install -r requirements.txt
```

И pip ставит ей всё разом нужных версий. Удобно.

Чтобы не писать `requirements.txt` руками, можно попросить pip сгенерировать его автоматически на основе того, что у вас установлено:

```bash
pip freeze > requirements.txt
```

## Виртуальные окружения — зачем они нужны

Тут начинается самое важное. Представьте такую ситуацию:

- Для проекта А вам нужна `pandas` версии 1.5
- Для проекта Б нужна `pandas` версии 2.2

Если устанавливать обе версии в систему — будет конфликт. На одном компьютере не может одновременно жить две версии одного пакета.

Решение — **виртуальное окружение**. Это отдельная папочка-«песочница», внутри которой живёт своя копия Python и свой набор пакетов. Для каждого проекта — своё окружение. Что в одном поставлено — никак не влияет на другое.

### Создание виртуального окружения

В Python для этого есть встроенный модуль `venv`. Переходим в папку проекта и пишем:

```bash
python -m venv venv
```

Здесь:
- `python -m venv` — запустить модуль `venv`
- последний `venv` — имя папки, в которой будет жить окружение (можно назвать как угодно, но `venv` или `.venv` — стандарт)

После выполнения рядом с вашим кодом появится папка `venv/` с копией интерпретатора Python внутри.

### Активация окружения

Чтобы pip и python начали работать **внутри** этого окружения, его нужно активировать.

На **Linux / macOS**:

```bash
source venv/bin/activate
```

На **Windows** (в PowerShell):

```bash
venv\Scripts\activate
```

После активации в начале строки терминала появится приставка `(venv)` — это знак, что вы внутри окружения. Теперь любая команда `pip install ...` будет ставить пакет не в систему, а в эту самую песочницу.

### Выход из окружения

```bash
deactivate
```

Приставка `(venv)` исчезнет — вы снова в системе.

### Типичный рабочий процесс

```bash
# 1. Создали папку проекта и зашли в неё
mkdir my_project
cd my_project

# 2. Создали виртуальное окружение
python -m venv venv

# 3. Активировали
source venv/bin/activate

# 4. Установили нужные пакеты
pip install requests pandas

# 5. Сохранили список зависимостей
pip freeze > requirements.txt

# 6. Пишем код, работаем...

# 7. Закончили — деактивировали
deactivate
```

Папку `venv/` обычно **не добавляют в Git** — её содержимое легко восстановить из `requirements.txt`. Поэтому её прописывают в `.gitignore`.

## Откуда pip берёт пакеты

По умолчанию — с **PyPI** (pypi.org). Можно зайти туда через браузер, поискать пакет, почитать описание, посмотреть статистику скачиваний. Это очень полезная привычка — перед установкой пакета убедиться, что он живой, активно поддерживается и его реально используют.

На что смотреть на странице пакета:
- **дата последнего релиза** — если пакет не обновлялся 5 лет, это подозрительно
- **количество скачиваний** — популярность как косвенный признак качества
- **ссылка на репозиторий** (обычно GitHub) — можно посмотреть, сколько у проекта звёзд и открытых багов
- **документация** — есть ли она и понятная ли

## Альтернативные инструменты (для общего развития)

`pip` — стандарт, но мир не стоит на месте. Вы можете встретить:

- **poetry** — более современный менеджер, который объединяет работу с пакетами и виртуальными окружениями в одном инструменте
- **uv** — очень быстрый менеджер, написанный на Rust, в последние пару лет набирает большую популярность
- **conda** — отдельный менеджер, популярный в научных кругах (data science, биоинформатика)

Все они решают примерно одну задачу, просто по-разному. Для учебных целей и большинства небольших проектов `pip + venv` — более чем достаточно.

## Шпаргалка

| Команда | Что делает |
|---|---|
| `pip install имя_пакета` | установить пакет |
| `pip install имя_пакета==1.2.3` | установить конкретную версию |
| `pip install -r requirements.txt` | установить всё из файла |
| `pip uninstall имя_пакета` | удалить пакет |
| `pip list` | показать установленные пакеты |
| `pip show имя_пакета` | подробности о пакете |
| `pip install --upgrade имя_пакета` | обновить пакет |
| `pip freeze > requirements.txt` | сохранить список зависимостей в файл |
| `python -m venv venv` | создать виртуальное окружение |
| `source venv/bin/activate` | активировать (Linux/macOS) |
| `venv\Scripts\activate` | активировать (Windows) |
| `deactivate` | выйти из окружения |
