# Лекция: Объектно-ориентированное программирование (ООП)

## Часть 1. ООП в общем смысле

### 1.1. Зачем вообще нужно ООП

Сегодня мы разберём один из главных подходов к организации кода — объектно-ориентированное программирование. Чтобы понять, зачем оно нужно, представьте, что мы пишем программу для интернет-магазина.

Без ООП мы бы хранили товар как словарь:

```python
product = {'name': 'Кофе', 'price': 500, 'stock': 10}
```

А все действия — отдельными функциями, которые принимают этот словарь:

```python
def apply_discount(product, percent):
    product['price'] = product['price'] * (1 - percent / 100)

def reduce_stock(product, amount):
    product['stock'] -= amount

def is_available(product):
    return product['stock'] > 0
```

Пока товар один — всё нормально. Но когда у нас десятки таких структур (товары, клиенты, заказы, корзины), и для каждой по 5–10 функций, мы тонем в этом коде. Данные отдельно, поведение отдельно, и связь между ними держится только в голове у программиста.

**ООП предлагает другой подход:** данные и поведение объединяются в одной сущности — *объекте*. Объект «Товар» сам знает свою цену, сам умеет применять к себе скидку, сам умеет списываться со склада.

### 1.2. Класс и объект

Это два главных понятия, которые нужно сразу различать.

- **Класс** — это шаблон, форма, чертёж. Описание того, какими должны быть объекты этого типа.
- **Объект** (или экземпляр) — это конкретная вещь, созданная по чертежу.

Аналогия: класс — это форма для печенья, а объекты — сами печеньки. Форма одна, а печенек можно напечь сколько угодно, и каждая будет отдельной.

Другой пример: класс «Человек» описывает, что у человека есть имя и возраст и он умеет здороваться. А объекты — это конкретные люди: Алиса 25 лет, Боб 30 лет. Оба — экземпляры класса «Человек», но это разные сущности.

### 1.3. Четыре кита ООП

В любом учебнике по ООП вы встретите эти четыре принципа.

**Инкапсуляция.** Данные и методы, которые с ними работают, упакованы в одном объекте. Внешний код взаимодействует с объектом через его методы, не лазая во внутренности. Например, у объекта «Счёт в банке» есть метод `withdraw(amount)`, но прямого доступа к балансу извне нет — иначе можно было бы сломать инвариант (например, сделать баланс отрицательным, минуя проверки).

**Наследование.** Один класс может быть основан на другом. Если у нас есть класс `Животное`, мы можем создать класс `Собака`, который автоматически получит всё, что есть у `Животное`, и добавит своё. Это позволяет переиспользовать код.

**Полиморфизм.** Одно и то же действие может работать по-разному для разных объектов. Метод `говорить()` у собаки скажет «Гав», у кошки — «Мяу», у человека — «Привет». Мы вызываем один и тот же метод, но результат зависит от типа объекта.

**Абстракция.** Мы прячем сложность за простым интерфейсом. Когда вы вызываете `list.sort()`, вам всё равно, какой алгоритм сортировки внутри. Объект сам разберётся, как себя отсортировать.

## Часть 2. ООП в Python

### 2.1. Определяем класс

В Python класс определяется ключевым словом `class`. Самый минимальный класс выглядит так:

```python
class Person:
    pass
```

`pass` означает «здесь ничего нет», но Python требует какого-то тела у класса. Создаём объект этого класса:

```python
someone = Person()
print(someone)
# <__main__.Person object at 0x1006f3fd0>
```

Обратите внимание: чтобы создать объект, мы пишем имя класса со скобками — как будто вызываем функцию. Это и называется *инстанциирование* — создание экземпляра.

### 2.2. Метод `__init__` и `self`

Пустой класс бесполезен — у объектов нет ни данных, ни поведения. Добавим инициализацию:

```python
class Person:
    def __init__(self, name):
        self.name = name
```

Разберём, что здесь происходит:

- `__init__` — это специальный метод, который вызывается автоматически при создании объекта. Его называют *конструктор* (хотя формально в Python конструктор — это `__new__`, но на практике мы почти всегда работаем с `__init__`).
- `self` — это ссылка на сам создаваемый объект. Через `self` мы внутри класса обращаемся к данным и методам конкретного экземпляра.
- `self.name = name` — сохраняем переданное значение в атрибуте объекта.

Используем класс:

```python
hunter = Person('Elmer Fudd')
print(hunter.name)   # Elmer Fudd
```

Что произошло пошагово, когда мы написали `Person('Elmer Fudd')`:

1. Python нашёл определение класса `Person`.
2. Создал в памяти новый пустой объект.
3. Вызвал у него метод `__init__`, передав сам объект как `self`, а строку `'Elmer Fudd'` — как `name`.
4. Внутри `__init__` строка сохранилась как `self.name`.
5. Готовый объект вернулся, и мы привязали его к имени `hunter`.

### 2.3. Методы экземпляра

Метод — это функция внутри класса. Первым параметром у неё всегда идёт `self`:

```python
class Person:
    def __init__(self, name):
        self.name = name

    def greet(self):
        print(f'Привет, я {self.name}')

alice = Person('Алиса')
alice.greet()        # Привет, я Алиса
```

Когда вы пишете `alice.greet()`, Python автоматически передаёт `alice` в метод как `self`. Это эквивалентно `Person.greet(alice)` — можно даже так написать, и сработает, но нормально так никто не пишет.

### 2.4. Несколько объектов одного класса

Сила ООП проявляется, когда у нас много объектов:

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def introduce(self):
        print(f'Меня зовут {self.name}, мне {self.age} лет')

alice = Person('Алиса', 25)
bob = Person('Боб', 30)
charlie = Person('Чарли', 22)

for person in [alice, bob, charlie]:
    person.introduce()

# Меня зовут Алиса, мне 25 лет
# Меня зовут Боб, мне 30 лет
# Меня зовут Чарли, мне 22 лет
```

Каждый объект хранит свои собственные данные. У `alice` свой `self.name`, у `bob` — свой. Методы при этом одни и те же на всех (хранятся в классе, а не дублируются в каждом объекте).

### 2.5. Атрибуты класса vs атрибуты экземпляра

Атрибут можно объявить двумя способами — на уровне класса или на уровне экземпляра.

```python
class Dog:
    species = 'Canis familiaris'   # атрибут КЛАССА — общий для всех

    def __init__(self, name):
        self.name = name           # атрибут ЭКЗЕМПЛЯРА — у каждого свой

rex = Dog('Рекс')
buddy = Dog('Бадди')

print(rex.name)         # Рекс
print(buddy.name)       # Бадди
print(rex.species)      # Canis familiaris
print(buddy.species)    # Canis familiaris
print(Dog.species)      # Canis familiaris — можно и через класс
```

Атрибут класса — один на всех. Атрибут экземпляра — у каждого объекта свой.

### 2.6. Полный пример: класс `Product`

Соберём в кучу всё, что разобрали:

```python
class Product:
    tax_rate = 0.20   # атрибут класса: НДС одинаков для всех товаров

    def __init__(self, name, price, stock):
        self.name = name
        self.price = price
        self.stock = stock

    def apply_discount(self, percent):
        self.price = self.price * (1 - percent / 100)

    def reduce_stock(self, amount):
        if amount > self.stock:
            print(f'Недостаточно товара: на складе {self.stock}')
            return
        self.stock -= amount

    def is_available(self):
        return self.stock > 0

    def price_with_tax(self):
        return self.price * (1 + Product.tax_rate)


coffee = Product('Кофе', 500, 10)
coffee.apply_discount(15)
print(coffee.price)              # 425.0
print(coffee.price_with_tax())   # 510.0
coffee.reduce_stock(3)
print(coffee.stock)              # 7
print(coffee.is_available())     # True
```

Сравните с самым началом лекции: всё, что было разрозненными функциями и словарём, собралось в одну осмысленную сущность.

### 2.7. Наследование

Допустим, у нас уже есть класс `Car`:

```python
class Car:
    def exclaim(self):
        print("Я машина!")
```

И мы хотим создать класс `Yugo` — это тоже машина, но с особенностями. Можно скопировать код, но это плохо. Правильное решение — наследование:

```python
class Yugo(Car):
    pass

give_me_a_car = Car()
give_me_a_yugo = Yugo()

give_me_a_car.exclaim()    # Я машина!
give_me_a_yugo.exclaim()   # Я машина!
```

Класс `Yugo` указан как наследник `Car` (имя родителя в скобках). Он автоматически получил метод `exclaim`, ничего не делая. Здесь `Car` называют *родительским классом* (или базовым, или суперклассом), а `Yugo` — *дочерним* (или подклассом).

### 2.8. Перегрузка методов

Наследник может *переопределить* метод родителя — заменить его на свой:

```python
class Car:
    def exclaim(self):
        print("Я машина!")

class Yugo(Car):
    def exclaim(self):
        print("Я Yugo! Похож на машину, но более Yugo-образный.")

Car().exclaim()    # Я машина!
Yugo().exclaim()   # Я Yugo! Похож на машину, но более Yugo-образный.
```

Это называется *перегрузка* (override). Когда мы вызываем метод у объекта, Python сначала ищет его в самом классе объекта, и только если там нет — поднимается к родителю.

Перегружать можно и `__init__`:

```python
class Person:
    def __init__(self, name):
        self.name = name

class MDPerson(Person):
    def __init__(self, name):
        self.name = "Доктор " + name

class JDPerson(Person):
    def __init__(self, name):
        self.name = name + ", эсквайр"

print(Person('Иванов').name)     # Иванов
print(MDPerson('Иванов').name)   # Доктор Иванов
print(JDPerson('Иванов').name)   # Иванов, эсквайр
```

### 2.9. Добавление новых методов

Наследник может не только переопределять старые методы, но и добавлять свои:

```python
class Car:
    def exclaim(self):
        print("Я машина!")

class Yugo(Car):
    def exclaim(self):
        print("Я Yugo!")

    def need_a_push(self):
        print("Помогите подтолкнуть...")

yugo = Yugo()
yugo.exclaim()       # Я Yugo!
yugo.need_a_push()   # Помогите подтолкнуть...

car = Car()
car.need_a_push()    # AttributeError: у Car нет такого метода
```

### 2.10. `super()` — обращение к родителю

Часто наследник хочет *расширить* поведение родителя, а не заменить его полностью. Например, родитель уже умеет инициализировать имя, а нам нужно добавить email. Делать всё с нуля — потеря выгод наследования. Правильный путь — вызвать метод родителя через `super()`:

```python
class Person:
    def __init__(self, name):
        self.name = name

class EmailPerson(Person):
    def __init__(self, name, email):
        super().__init__(name)   # вызвали __init__ родителя
        self.email = email       # добавили своё

bob = EmailPerson('Боб', 'bob@mail.com')
print(bob.name)    # Боб
print(bob.email)   # bob@mail.com
```

`super().__init__(name)` означает: «найди родительский класс и вызови его `__init__`, передав `name`». Это избавляет нас от дублирования кода, и если завтра в `Person.__init__` добавится новая логика — `EmailPerson` её автоматически унаследует.

### 2.11. Цепочка наследования: пример

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def describe(self):
        print(f'Это {self.name}')

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)
        self.breed = breed

    def describe(self):
        super().describe()
        print(f'Порода: {self.breed}')

class GuideDog(Dog):
    def __init__(self, name, breed, owner):
        super().__init__(name, breed)
        self.owner = owner

    def describe(self):
        super().describe()
        print(f'Хозяин: {self.owner}')


rex = GuideDog('Рекс', 'Лабрадор', 'Анна')
rex.describe()
# Это Рекс
# Порода: Лабрадор
# Хозяин: Анна
```

Каждый уровень добавляет свой кусочек, не переписывая работу родителя.

### 2.12. Полиморфизм и утиная типизация

В Python работает принцип «утиной типизации»: *если что-то крякает как утка и плавает как утка, то это утка*. Иначе говоря, Python не проверяет тип объекта — он просто пытается вызвать у него нужный метод.

```python
class Hunter:
    def says(self):
        return 'Я охочусь на кроликов'

class Rabbit:
    def says(self):
        return 'Что нового, док?'

class BabblingBrook:   # совсем не связан с предыдущими
    def says(self):
        return 'Журчу-журчу'


def let_them_speak(obj):
    print(obj.says())

for character in [Hunter(), Rabbit(), BabblingBrook()]:
    let_them_speak(character)

# Я охочусь на кроликов
# Что нового, док?
# Журчу-журчу
```

Функции `let_them_speak` всё равно, какого типа объект ей передали. Лишь бы у него был метод `says()`. В этом сила полиморфизма в Python: классы не обязаны быть связаны наследованием, чтобы вести себя одинаково в каком-то контексте.

### 2.13. Особые (магические) методы

Это методы с двойным подчёркиванием по краям: `__init__`, `__str__`, `__eq__` и т.д. Их вызывает не пользователь напрямую, а Python — в ответ на разные операции.

Без них объект выглядит уныло:

```python
class Word:
    def __init__(self, text):
        self.text = text

w = Word('привет')
print(w)        # <__main__.Word object at 0x10c0...>
print(w == Word('привет'))   # False — это два разных объекта в памяти
```

Добавим магических методов:

```python
class Word:
    def __init__(self, text):
        self.text = text

    def __str__(self):                  # как объект печатается
        return self.text

    def __repr__(self):                 # как объект показывается в REPL
        return f'Word("{self.text}")'

    def __eq__(self, other):            # как сравнивается через ==
        return self.text.lower() == other.text.lower()

    def __len__(self):                  # как работает len()
        return len(self.text)


w1 = Word('Привет')
w2 = Word('привет')
print(w1)              # Привет
print(repr(w1))        # Word("Привет")
print(w1 == w2)        # True (сравниваем без учёта регистра)
print(len(w1))         # 6
```

Полезные магические методы для арифметики и сравнения:

| Метод | Операция |
|---|---|
| `__eq__(self, other)` | `self == other` |
| `__ne__(self, other)` | `self != other` |
| `__lt__(self, other)` | `self < other` |
| `__gt__(self, other)` | `self > other` |
| `__add__(self, other)` | `self + other` |
| `__sub__(self, other)` | `self - other` |
| `__mul__(self, other)` | `self * other` |
| `__str__(self)` | `str(self)`, `print(self)` |
| `__repr__(self)` | `repr(self)`, REPL |
| `__len__(self)` | `len(self)` |

Пример с арифметикой — класс «Деньги»:

```python
class Money:
    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        return Money(self.amount + other.amount)

    def __sub__(self, other):
        return Money(self.amount - other.amount)

    def __str__(self):
        return f'{self.amount} руб.'


a = Money(100)
b = Money(50)
print(a + b)    # 150 руб.
print(a - b)    # 50 руб.
```

### 2.14. Композиция

Наследование — мощный инструмент, но не единственный. Иногда правильнее не «наследовать», а «содержать». Это называется *композиция*.

Правило простое:
- если объект **является** чем-то — это наследование (Yugo *является* машиной);
- если объект **имеет** что-то — это композиция (у Утки *есть* клюв и хвост).

```python
class Bill:
    def __init__(self, description):
        self.description = description

class Tail:
    def __init__(self, length):
        self.length = length

class Duck:
    def __init__(self, bill, tail):
        self.bill = bill
        self.tail = tail

    def about(self):
        print(f'У этой утки {self.bill.description} клюв и {self.tail.length} хвост')


bill = Bill('широкий оранжевый')
tail = Tail('длинный')
duck = Duck(bill, tail)
duck.about()
# У этой утки широкий оранжевый клюв и длинный хвост
```

Класс `Duck` *использует* объекты `Bill` и `Tail`, но не наследуется от них. Это даёт большую гибкость: завтра мы сможем заменить хвост на другой, не трогая остальное.

### 2.15. Свойства (`property`)

В других языках принято делать атрибуты приватными и писать к ним геттеры и сеттеры:

```python
# так делают в Java/C#
person.get_name()
person.set_name('Алиса')
```

В Python это не принято. Атрибуты у нас открытые, и обращаемся мы к ним напрямую: `person.name`. Но что, если нам нужно при чтении или записи делать какие-то проверки? Для этого есть декоратор `@property`:

```python
class Person:
    def __init__(self, name):
        self._name = name           # подчёркивание = "не трогайте напрямую"

    @property
    def name(self):                 # геттер
        print('читаем имя')
        return self._name

    @name.setter
    def name(self, value):          # сеттер
        print('пишем имя')
        if not value:
            raise ValueError('Имя не может быть пустым')
        self._name = value


p = Person('Алиса')
print(p.name)        # читаем имя \n Алиса
p.name = 'Боб'       # пишем имя
# p.name = ''        # ValueError: Имя не может быть пустым
```

Для пользователя это выглядит как обычный атрибут (`p.name`), но за ним стоят функции с проверками. Это и есть «питоновский» способ инкапсуляции.

### 2.16. Когда использовать классы, а когда — нет

- Используйте классы, когда нужно **много объектов одного типа**, у каждого свои данные, но общее поведение.
- Если объект всего один — обычно достаточно модуля.
- Если данные простые и без поведения — словарь, кортеж или именованный кортеж проще и быстрее класса.
- Совет Гвидо ван Россума: «Избегайте усложнения структур данных. Кортежи лучше объектов. Используйте больше чисел, строк, кортежей, списков, множеств, словарей».

Классы — мощный инструмент, но не молоток, которым нужно колотить по всем гвоздям. Иногда простая функция с парой словарей читается лучше, чем иерархия из пяти классов.

## Краткие итоги

1. **Класс** — шаблон, **объект** — экземпляр класса.
2. `__init__` инициализирует объект; `self` — ссылка на сам объект.
3. Атрибуты экземпляра — у каждого объекта свои; атрибуты класса — общие.
4. **Наследование** позволяет переиспользовать код: `class Child(Parent)`.
5. **Перегрузка** — переопределение метода родителя в наследнике.
6. `super()` вызывает метод родителя — полезно при расширении логики.
7. **Полиморфизм/утиная типизация** — Python смотрит не на тип, а на наличие нужного метода.
8. **Магические методы** (`__str__`, `__eq__`, `__add__`, ...) делают объекты «питоновскими».
9. **Композиция** часто лучше наследования: «иметь» гибче, чем «быть».
10. Свойства (`@property`) — питоновский способ контролировать доступ к данным.
